# Boundary Source Notes

## Prototype Boundary Workflow

Public GitHub boundary/name sources can be used to test the pipeline, inspect geometry coverage, normalize names, and perform prototype spatial joins. They must remain labeled as `prototype-public-source` or `public_prototype`.

## Required Checks

Before using any public boundary file, check:

- CRS and reprojection behavior.
- Geometry validity.
- Geometry type.
- Feature count.
- AP coverage.
- District and mandal/subdistrict coverage.
- District splits and current administrative names.
- Mandal spelling and aliases.
- Recency.
- License terms.

## Official Replacement

Official APWRIMS/APSAC/RTGS mandal boundaries are required before official mandal-level outputs are claimed. Public prototype boundaries must not be silently promoted to official status.
