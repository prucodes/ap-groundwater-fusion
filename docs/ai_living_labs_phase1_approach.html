Phase-1 Approach — for discussion

My understanding of the deliverable and how I'd approach it, ahead of your technical proposal. This is a discussion input and a phasing view — not a competing architecture spec. I'd expect to refine it against your design.

1 What I take the deliverable to be

Reading the GO together with our call: the buildable software piece is a sovereign AI control plane on top of a managed Kubernetes/OpenShift base — letting defined cohorts (researchers, startups/developers, students) self-serve GPU compute and open-source models, with usage metered and attributable per tenant, and the whole thing operable by the Foundation after handoff. Hardware/data-center and government-data governance stay out of this lane. Principle: managed-first, portable, open-source, everything-as-code.

2 Phase-1 scope

In scope

  • Identity + RBAC (one model, enforced at portal / cluster / API)
  • Resource request & approval → GPU/CPU/storage quotas + workspace provisioning
  • Model & tool catalog (open-source serving; notebook / Open-WebUI-style access)
  • Usage metering + cost attribution — the hard core (§3)
  • Audit logging on every action
  • One reference app — secure RAG over public govt docs (citations; "no source, no answer")

Out of scope (for now — by design)

  • Real government datasets / data-governance (parked until policy is set; kept integration-ready)
  • Physical data-center, GPU procurement, NVIDIA MoU, institution setup
  • Production security certification & citizen-scale apps
  • Fine-tuning for everyone (offer later as a controlled researcher/startup workload)

Personas: go deep on 2–3 first (researcher, startup/developer, foundation admin); students & departments shown on the roadmap, not built day one.

4 The hard core — metering & cost attribution

No single tool does this across mixed workloads, so it's the one component I'd treat as first-class: compute usage (GPU-hours per namespace, OpenCost/Kubecost-style) + model serving (per-token, logged at a gateway in front of the serving stack) → a unified per-tenant ledger for showback/billing, with subsidy rules per cohort applied there. That ledger is exactly the "at-cost + subsidize chosen cohorts" lever the state wants. Everything else in Phase 1 is integration of open-source parts; this is the real build.

5 How I'd de-risk the build
Not vibe coding — AI-assisted engineering with governance. Secure-by-design from day one (least-privilege RBAC, audit on every action, input validation, synthetic/public data only — no real AP data in any external tool); maintainability as a first-class deliverable (typed code, tests, ADRs, auto-generated repo docs, GitOps, runbooks) so the Foundation's team can operate it after we step away. AI accelerates scaffolding, tests, and docs; humans own architecture, security, and review. Prototype is explicitly labelled reference-grade — production needs infra/security sign-off, load testing, and staged rollout.

  • 5Phase-1 scale / SLA target (concurrent users, uptime) — so we right-size, not over-build.
